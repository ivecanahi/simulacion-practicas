4.  Marco Conceptual

4.1 Modelo matemático y simulación

Un sistema es un conjunto de entidades que interactúan para cumplir un propósito, y un modelo es una representación simplificada de ese sistema que se usa para estudiarlo [3]. Cuando el modelo se expresa con relaciones lógicas y cuantitativas se denomina modelo matemático. Si es lo bastante simple, puede resolverse de forma analítica; si no, se evalúa numéricamente en un computador. Este proceso se conoce como simulación [3], [4].

Los modelos se clasifican como estáticos o dinámicos, según representen el sistema en un instante o su evolución en el tiempo, y como determinísticos o estocásticos, según contengan o no componentes aleatorios [3]. El modelo de esta práctica es estático y determinístico: para cada hora calcula un índice a partir de las condiciones de ese momento, y con las mismas entradas siempre produce el mismo resultado.

4.2 Variables, parámetros y relaciones

Las variables son las magnitudes que describen el estado del sistema y cambian entre observaciones. En esta práctica son la humedad, la nubosidad y la temperatura de cada hora. Los parámetros son valores constantes que fijan la forma del modelo durante una simulación: aquí, los pesos de cada variable, la tabla del factor de temperatura y los umbrales de clasificación. Las relaciones son las ecuaciones o reglas que conectan variables y parámetros para producir la salida [4].

4.3 Variables atmosféricas y precipitación

La precipitación requiere que el vapor de agua del aire se condense. La humedad relativa mide qué tan cerca está el aire de la saturación: cuando se acerca al 100 %, el vapor empieza a condensarse y se forman nubes y gotas [5]. La temperatura influye de forma inversa: el aire frío admite menos vapor antes de saturarse, por lo que, con el mismo contenido de agua, un descenso de temperatura eleva la humedad relativa y favorece la condensación [5]. La nubosidad indica la fracción del cielo cubierta por agua ya condensada. Estas relaciones justifican que el modelo asigne un índice mayor a humedad y nubosidad altas y a temperaturas bajas.

En meteorología es habitual construir pronósticos estadísticos que combinan varios predictores observados en un solo valor, ajustando el aporte de cada uno [6]. El índice de esta práctica sigue esa idea de forma simplificada.

4.4 Normalización e índice compuesto

Para combinar magnitudes con unidades distintas, primero se llevan a una escala común entre 0 y 1. La humedad y la nubosidad, expresadas en porcentaje, se dividen para 100. La temperatura se transforma en el factor Tf mediante una tabla decreciente: 1.00 para 10 °C o menos y 0.10 para 28 °C o más. Luego el índice se obtiene como un promedio ponderado:

I = WH·H + WN·N + WTf·Tf,    con WH + WN + WTf = 1

Como los pesos son positivos y suman 1, I es una combinación convexa de valores entre 0 y 1, así que también queda entre 0 y 1. Además, cada peso es la derivada parcial del índice respecto de su variable (∂I/∂H = WH): indica cuánto cambia I cuando esa variable aumenta en una unidad normalizada.

4.5 Clasificación por umbrales

El valor continuo de I se convierte en una categoría con la tabla de reglas de la guía:

Índice IEstado
I < 0.40Sin lluvia
0.40 ≤ I < 0.60Baja posibilidad
0.60 ≤ I < 0.75Lluvia probable
I ≥ 0.75Lluvia

Convertir un pronóstico continuo en categorías facilita su comunicación, pero un pronóstico solo es útil si es consistente con el conocimiento del fenómeno, si coincide con lo que realmente ocurre y si aporta valor a quien lo usa [7].

4.6 Verificación, validación y sensibilidad

La verificación comprueba que el programa implementa correctamente el modelo conceptual, y la validación comprueba que el modelo representa al sistema real con la precisión necesaria [8]. En esta práctica la verificación se hizo reproduciendo el ejemplo resuelto de la guía. La validación requeriría comparar el índice con registros reales de lluvia.

El análisis de sensibilidad estudia cómo cambia la salida de un modelo cuando cambian sus entradas o parámetros, e identifica cuáles influyen más [9]. Aquí se aplica al comparar el modelo original con uno que redistribuye los pesos.

5.  Procedimiento / Metodología Ejecutada

  1. Identificación del sistema. Se identificaron las variables de entrada (humedad, nubosidad y temperatura), los parámetros (pesos 0.5, 0.3 y 0.2, tabla de Tf y umbrales) y la relación matemática (promedio ponderado), según la guía de la práctica y las diapositivas del curso [10].
  2. Diseño del programa. Se usó la arquitectura Modelo-Vista-Controlador (MVC) para separar responsabilidades:
    • model.py: fórmula del índice, tabla de Tf y clasificación. No imprime ni grafica.
    • controller.py: datos de entrada de la guía y orquestación del cálculo.
    • view.py: tablas en consola y gráficas.
    • main.py: punto de entrada que une el flujo.
  3. Factor de temperatura. Para temperaturas que no aparecen en la tabla (15 °C y 17 °C) se tomó el siguiente escalón igual o mayor, con la misma lógica con que está redactada la tabla (≤ 10 °C, ≥ 28 °C). Así, 15 °C se trata como 16 °C (Tf = 0.70) y 17 °C como 18 °C (Tf = 0.60).
  4. Verificación con el ejemplo de la guía. Para humedad 90 %, nubosidad 80 % y 18 °C:

    H = 0.90,   N = 0.80,   Tf = 0.60

    I = 0.5(0.90) + 0.3(0.80) + 0.2(0.60) = 0.45 + 0.24 + 0.12 = 0.81

    El programa devuelve I = 0.81, igual que la guía. Con esto se dio por verificada la implementación.

  5. Simulación del día. Se calculó el índice y el estado para las nueve horas de la tabla de la guía, de 06:00 a 22:00.
  6. Ajuste del modelo. Se cambiaron solo los pesos a 0.4 / 0.3 / 0.3 (siguen sumando 1), dando más peso a la temperatura, y se volvió a llenar la tabla.
  7. Análisis. Se generaron cuatro gráficas, se calcularon estadísticas de cada modelo y se analizó matemáticamente la diferencia entre ambos.

6.4 Gráficas

El índice baja hasta su mínimo al mediodía (0.47 a las 12:00), cuando la temperatura es más alta (22 °C) y la nubosidad más baja (30 %). Por la tarde sube hasta su máximo a las 18:00 (0.885), cuando la humedad y la nubosidad superan el 90 % y la temperatura desciende. Desde las 16:00 ambos modelos predicen lluvia.

La relación entre temperatura y Tf es decreciente y escalonada: cada 2 °C el factor baja 0.10. Esto refleja que el aire frío se satura con más facilidad [5].

La humedad y la nubosidad siguen la misma tendencia: bajan al mediodía y suben por la tarde. Tf tiene el comportamiento inverso a la temperatura, con su mínimo a las 12:00. Las tres variables coinciden en señalar la tarde como el periodo más favorable para la lluvia, lo que explica el aumento del índice.

6.5 Análisis de sensibilidad e influencia de los parámetros

Como cada peso es la derivada parcial del índice respecto de su variable, los pesos miden directamente la sensibilidad del modelo:

Cambio en la entradaEfecto en I (original)Efecto en I (ajustado)
Humedad +10 puntos (ΔH = 0.10)+0.050+0.040
Nubosidad +10 puntos (ΔN = 0.10)+0.030+0.030
Temperatura +2 °C (ΔTf = −0.10)−0.020−0.030

En el modelo original la humedad es la variable más influyente: pesa 2.5 veces más que la temperatura. Al restar el índice original del ajustado se obtiene una expresión sencilla:

Iajustado − Ioriginal = (0.4 − 0.5)·H + (0.3 − 0.2)·Tf = 0.1·(Tf − H)

Por lo tanto, el modelo ajustado da un índice mayor solo en las horas en que Tf > H. Eso ocurre únicamente a las 06:00 (0.80 > 0.65, el índice sube de 0.605 a 0.620). A las 08:00 ambos valores son iguales (0.70) y el índice no cambia. En el resto del día la humedad supera a Tf y el índice baja entre 0.008 y 0.028. Como la mayor diferencia es de apenas 0.028, ninguna hora cambia de estado: con estos datos, el modelo es robusto ante esa redistribución de pesos [9].

7.  Preguntas de Control

Nota: las preguntas 3 a 5 se refieren al modelo de crecimiento exponencial P(t) = P0·ert y se responden en términos generales.

  1. ¿Qué es un modelo matemático?

    Es una representación simplificada de un fenómeno real mediante variables, parámetros y relaciones matemáticas, que permite explicar o predecir su comportamiento [3]. En esta práctica, la fórmula del índice representa la posibilidad de lluvia a partir de tres variables atmosféricas.

  2. ¿Cuál es la diferencia entre variable y parámetro?

    Una variable cambia con cada observación del sistema (H, N y Tf cambian hora a hora). Un parámetro es un valor fijo que define la forma del modelo durante la simulación (los pesos 0.5, 0.3 y 0.2 y los umbrales 0.40, 0.60 y 0.75). Cambiar un parámetro significa cambiar el modelo, como se hizo en el modelo ajustado.

  3. ¿Qué representa P₀?

    Es la condición inicial: el valor de la magnitud (por ejemplo, la población) en el instante t = 0, desde el cual el modelo calcula su evolución.

  4. ¿Qué ocurre cuando r < 0?

    El término ert disminuye con el tiempo, por lo que la magnitud decrece de forma exponencial y se acerca a 0 sin llegar a ser negativa.

  5. ¿Qué limitaciones tiene el modelo exponencial?

    Supone una tasa constante y recursos ilimitados, por lo que crece sin límite. No considera factores externos que frenan el proceso (capacidad de carga, competencia, eventos aleatorios), así que solo es realista en intervalos cortos.

8.  Conclusiones

  • Construir un modelo matemático exige identificar primero las variables, los parámetros y la relación entre ellos. Con eso definido, la implementación en Python es directa y la arquitectura MVC permite cambiar parámetros sin modificar el resto del programa.
  • La normalización a la escala 0–1 y los pesos que suman 1 garantizan que el índice también quede entre 0 y 1, lo que lo hace comparable entre horas e interpretable con la tabla de reglas.
  • El modelo predice lluvia desde las 16:00 hasta las 22:00, cuando la humedad y la nubosidad son altas y la temperatura baja. Esto es coherente con la física de la condensación descrita en el marco conceptual.
  • Los pesos son la sensibilidad del modelo: en el original, la humedad domina el índice (peso 0.5).
  • La diferencia entre el modelo ajustado y el original es 0.1·(Tf − H). Por eso el ajuste solo sube el índice cuando Tf supera a H. Con estos datos el cambio máximo es de 0.028 y ninguna hora cambia de estado.
  • La implementación quedó verificada con el ejemplo de la guía (I = 0.81). Para validarla haría falta compararla con registros reales de lluvia.

9.  Recomendaciones

  • Validar el modelo con datos meteorológicos reales (por ejemplo, horas en que efectivamente llovió) y ajustar los pesos para maximizar los aciertos, en lugar de fijarlos a criterio [8], [7].
  • Interpolar el factor de temperatura de forma lineal para valores intermedios, en vez de usar escalones, para evitar saltos bruscos del índice.
  • Aplicar un análisis de sensibilidad global, variando todos los pesos a la vez, para identificar combinaciones que sí cambien la clasificación [9].
  • Incorporar otras variables relevantes para la precipitación, como la presión atmosférica o el punto de rocío [5], [6].
  • Mantener la separación entre modelo y presentación (MVC) para facilitar pruebas y cambios futuros.

Fórmula del índice y factor de temperatura (model.py):

def temperature_factor(temp):
    if temp <= TEMPERATURE_TABLE[0][0]:
        return TEMPERATURE_TABLE[0][1]
    if temp >= TEMPERATURE_TABLE[-1][0]:
        return TEMPERATURE_TABLE[-1][1]
    for t_table, tf in TEMPERATURE_TABLE:
        if temp <= t_table:
            return tf

def compute_index(humidity, cloudiness, temp, weights):
    w_h, w_n, w_tf = weights
    h = normalize(humidity)
    n = normalize(cloudiness)
    tf = temperature_factor(temp)
    index = w_h * h + w_n * n + w_tf * tf
    return h, n, tf, index

def classify_state(index):
    if index < 0.40:
        return "Sin lluvia"
    if index < 0.60:
        return "Baja posibilidad"
    if index < 0.75:
        return "Lluvia probable"
    return "Lluvia"
